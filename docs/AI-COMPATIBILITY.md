# MonsterMaze AI compatibility

MonsterMazeEngine is the pure simulation counterpart to MonsterMazeAI. The same learned policy must be usable in the engine, the MonsterMazeAI simulator, and the Minecraft 1.8 adapter without translating its action semantics.

## Action contract

| Index | Field | Range |
|---:|---|---|
| 38 | forward | -1..1 |
| 39 | strafe | -1..1 |
| 40 | jump | 0/1 |
| 41 | sprint | 0/1 |
| 42 | yawDelta | -30..30 degrees |
| 43 | ability | 0/1 |

`yawDelta` is a per-tick change to the current yaw, not an absolute heading.

## State/feature contract

`PolicyLearningFeatures` emits the same 52 feature names and index order as MonsterMazeAI.

The first 38 values describe state. Indexes 38-43 are the six action values. Indexes 44-51 describe physical route context, including turn count and gap-jump opportunities.

The engine may keep a different world origin internally. The feature encoder converts positions to the same 99x99 logical coordinate space used by the AI.

## Model contract

`PolicyActionModel` consumes the same `policy-model.json` format generated by MonsterMazeAI policy training: 52 inputs, 48 hidden units, 24 hidden units, one scalar output, ReLU hidden layers, training input mean/std, and target mean/std/bounds.

A model trained against source-faithful engine rollouts can therefore be loaded by the existing MonsterMazeAI policy inference path, provided it was trained with the same feature contract and promoted through the existing holdout gate.

## Mechanics contract

The engine follows the MonsterMazeAI common source-faithful simulator for 1.8 movement and jump lock, physical floor/AABB collision, monster random walk and waypoint movement, monster contact/knockback, Safe Pad timing/geometry, center deterioration, kit resource/ability timing, stage progression, and monster spawning.

Differential trace tests against live Minecraft 1.8 remain the final validation for behaviours that depend on server/client implementation details.
